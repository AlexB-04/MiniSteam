# MiniSteam v3.3 — Game Build Integrity Report

## Trigger

`First Guest: Solitaire` exposed a launcher/update integrity problem:

- published build: `1.0.1`
- ZIP contents: 5 files
- MiniSteam displayed: `Installed · v1.0.1`
- installed directory observed after update: only `FirstGuestSolitaire.exe`
- the required `FirstGuestSolitaire.ps1` and the other archive files were missing

The original uploaded `1.0.1` ZIP was independently extracted and confirmed to contain all five files.

## Important source observation

The supplied v3.2 source snapshot already contains staging extraction followed by a directory move of the whole staging directory. That source path should normally preserve all extracted files. Therefore the observed one-file installation cannot be proven from source inspection alone to originate from a single specific line in `InstallationService`.

Possible explanations include a stale/different Desktop binary being run or an unobserved runtime path. v3.3 therefore does not merely add another copy operation. It adds explicit integrity guarantees so a partial install/update can no longer be silently accepted as successful.

## v3.3 protection

1. Server reports archive file count and total uncompressed bytes.
2. Desktop downloads the ZIP and checks compressed download size as before.
3. ZIP is extracted into a staging directory.
4. Every extracted file is recorded with relative path and size.
5. Extracted inventory is checked against server archive statistics.
6. Every staged file is verified on disk.
7. Previous installation is moved to a backup directory.
8. Staging directory is moved to the final game directory.
9. Every build file is verified again in the final directory.
10. Only then is the installed-version manifest updated and the backup removed.
11. v3.3 stores the file inventory in the local manifest and validates it on later refreshes.
12. Legacy installs without an inventory are checked against server archive count/size; clearly incomplete installs become `BROKEN` and expose `REINSTALL`.

## First Guest: Solitaire validation data

The archived `1.0.1` build stored in the supplied MiniSteam project contains:

- `FirstGuestSolitaire.exe`
- `FirstGuestSolitaire.ps1`
- `FirstGuestSolitaire_StoreArtwork.png`
- `README.txt`
- `build-manifest.json`

Archive file count: **5**

Uncompressed bytes: **3,765,259**

A simulated legacy directory containing only `FirstGuestSolitaire.exe` is detected as incomplete by the new v3.3 archive-statistics fallback.

## Manual regression check on Windows

After building/running the v3.3 server and Desktop client:

1. Refresh Library.
2. The current incomplete Solitaire installation should become `Build integrity failed · reinstall required` and show `REINSTALL`.
3. Click `REINSTALL`.
4. After completion, the card should report `Installed · v1.0.1 · 5 files verified`.
5. Inspect `C:\Users\User\Games\MiniSteam\12-First Guest_ Solitaire` and confirm all five build files exist.
6. Click `PLAY` and confirm Solitaire launches without PowerShell intervention.
7. Delete one required installed file manually, refresh Library, and confirm the build changes to `BROKEN/REINSTALL` rather than remaining falsely installed.
8. Repeat with a Unity build later. A Unity build must retain its `.exe`, `*_Data` directory, DLLs, and all nested files.

## Validation limitation in this environment

The patch was structurally checked, XML files were parsed successfully, modified C# delimiters were checked, and the build archive/integrity logic was simulated against the supplied Solitaire archive. The current execution environment does not contain the .NET SDK, so `dotnet build` / `dotnet test` could not be run here. Final compile and runtime verification must be performed on the user's Windows/.NET 10 environment.
